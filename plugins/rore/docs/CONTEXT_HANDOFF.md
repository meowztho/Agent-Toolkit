# RORE handoff

## v0.16.1 current delta

Static Reconstruction now includes an optional rebuild-and-compare experiment when reference bytes, a source candidate and a suitable build path are actually available. It retains exact build and comparison provenance, raw differences and range-scoped conclusions; exact byte matches and progress percentages do not prove original source, runtime behavior or complete reconstruction. The broad coverage method separates exact, heuristic, copied, untested and unknown portions when reporting comparison progress. This adds no decomp.dev code, dashboard, online dependency, required objdiff provider or downstream product-build responsibility. No real target rebuild comparison was executed for this guidance-only release.

## v0.16.0 current delta

The optional Windows x64 Ghidra/JDK setup and copied-target analysis can now be invoked through a separate RORE-owned `rore-providers` MCP. It reuses the existing installer and adapter, runs explicit retained jobs with interrupted-worker detection, and exposes doctor/plan/status plus bounded hash-checked run, inventory and selected-function pseudocode pages. An analysis can provision the pinned pair on demand when absent; plugin startup does not install a provider. The existing Evidence MCP remains read-only. A real MCP setup job qualified an already installed local pair, a fresh installation from verified local release archives completed through MCP into a new root, and a combined absent-provider → automatic install → exact copied `where.exe` analysis job completed with verified import identity and paged pseudocode. A separate real analysis yielded 317 selected-function references. A live network download through MCP and arbitrary target coverage were not established by those runs. Dynamic debugger/tool installation remains a capability-first agent-mediated route, not a packaged universal installer.

## v0.15.1 current delta

The user-supplied native-tool integration research was compared with RORE's existing owners, methods and executable adapter. ## v0.14.0 current delta

RORE now derives a broad analysis scope from a named or unambiguously supplied reference and the user's investigation request, including earlier session permissions. It does not demand generic ownership/legal proof or per-method confirmation for extraction, decompilation, observation, bounded reversible local probes and needed contained user-scoped provider acquisition. Orchestration still checks target, environment, operation and effects internally; newly discovered accounts, remote services or material external effects do not silently inherit scope. The affected action waits for a focused answer while other in-scope investigation continues. Analysis, retention, sharing and redistribution remain separate. This changes guidance and the default prompt, not host approval controls or executable tool behavior.

## v0.4.2 baseline

RORE v0.4.2 preserves the v0.4.1 domain-neutral reconstruction boundary and adds three bounded reverse-engineering evidence hardenings without adding a new owner or downstream dependency.

The live boundary is:

```text
reference target
→ evidence acquisition and reconstruction
→ Evidence + Findings + Paths + reference-native Models
→ coverage / contradictions / unknowns
STOP
```

Removed active responsibilities: Product, Design-as-target-translation, Build, replica Verification/Parity, Market/Brand/Launch and Release. Useful reverse-engineering methods from those lanes were absorbed into Reconstruction or Evidence Review.

The user-supplied snapshots `replica-skill-main.zip` and `reverse-skill-main.zip` were re-inspected before the migration. The audit specifically restored/strengthened stable surface/flow identity, edge-state reconstruction, hypothesis/negative-evidence discipline, deadlock replanning, bias/context-pollution checks, protocol/mobile/web/differential analysis and perturbation-as-causal-instrument.

Do not reintroduce APC/project-compilation coupling into RORE. Downstream consumers may use RORE output, but RORE does not adapt Reference Truth for them.

v0.4.2 adds only:
- current-state observation-path liveness when a live claim has concrete stale/frozen/cached/replayed/disconnected-path risk, with the reverse guard that identical static observations alone do not prove failure;
- fresh/anti-anchored Evidence Review where feasible, while still reviewing the existing evidence graph read-only;
- explicit semantic-to-low-level descent for static/binary reconstruction when source/decompiler abstractions cannot discriminate a material hypothesis.

## Domain neutrality
RORE is domain-neutral. Games are a stress-test domain, not a primary target. Route from the unresolved knowledge/evidence boundary; domain-specific profiles are optional JIT method bundles only.
