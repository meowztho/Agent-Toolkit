# RORE User Vision

RORE is a domain-neutral reverse-engineering and reference-reconstruction method. It investigates an authorized reference system as deeply as technically possible within the authorized boundary, regardless of whether that system is a website, API, ERP, CRM, desktop/mobile application, protocol, binary, game or another digital system. The reference supplies its own behavior, architecture, state, data, flows, timing, failure modes and semantics. RORE discovers and preserves those rather than prematurely translating them into a cleaner or builder-oriented target design. A broad mission seeks all technically accessible information, including low-level structure, rather than stopping once one plausible implementation outline is available.

A broad mission may include surface observation, extraction/decompression, decompilation/disassembly, runtime and memory inspection, DOM/client/network observation, protocol recovery, data/schema inference, asset/resource analysis, cross-version comparison, public research, and controlled perturbation of authorized state to expose hidden causal structure. Which methods activate depends on the unresolved knowledge and evidence boundary, not on a privileged target domain.

RORE gathers technically accessible facts about the reference before anyone decides how to use them. A future project's likely needs do not justify dropping extractable architecture, behavior, interfaces, network interactions, assets, data semantics, low-level mechanisms or failure cases. Large systems require partitioned coverage and complete raw-material lineage rather than a short representative summary.

Games are useful stress-test targets because they can combine many interacting systems, but they are not a primary RORE domain. The method must remain equally applicable to web, API, enterprise, desktop, mobile, protocol and other system classes.

An investigation may involve several distinct references, for example two games whose mechanics or content might later be combined. RORE reconstructs the relevant code, state, asset and runtime contracts of each independently, using decompilation where it reveals hidden paths or candidate mod entry points. It then records observed extension surfaces and cross-reference correspondences or mismatches; it does not choose or implement the combination.

The desired result is auditable, replication-ready Reference Truth: reproducible Evidence, grounded Findings, connected Paths, reference-native Models, reference comparison cases, explicit contradictions, provenance, confidence, coverage and unknowns. Keep raw observations and their index separate from revisable interpretations and narrative in a portable handoff. At the requested scope, an independent implementation agent should normally work from RORE's findings even if the finished reference remains available. A remaining unknown records what was attempted, why it could not be recovered or inferred, and what a user or later investigation could still supply; a missing tool or failed download alone is not an irrecoverable reference fact.

Skills guide the investigation; the agent may use a qualified existing program, a narrow helper it writes, CLI or MCP as the question requires. No named repository, source project, analyzer or live download endpoint is a required RORE dependency. Internet access may help acquire tools and evidence, but loss of one provider triggers a different available method before the investigation stops. Controlled changes may be made to an authorized reference when their baseline, exact effects and recovery are traceable; an isolated copy is preferred when practical and representative, not required when it adds needless work.

When a user names or supplies a reference and asks RORE to investigate it, that request supplies the default broad analysis scope for the target. RORE uses the session context and existing permissions, including ordinary extraction, decompilation, observation, bounded reversible local probes and contained acquisition of needed freely available analysis tools; it does not demand a separate legal justification or keep stopping for methods the user did not explicitly list. It asks only when a material new target, account, access, cost, privilege or external-effect boundary cannot be resolved from context. Permission to investigate remains distinct from permission to publish or redistribute acquired material.

RORE stops before downstream product selection, project compilation, target architecture, implementation, replica QA, branding, launch or release.
