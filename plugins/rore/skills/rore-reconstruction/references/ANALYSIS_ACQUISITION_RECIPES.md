# Analysis Acquisition Recipes

Use when an unresolved reference question needs a concrete acquisition route and no integrated analysis suite is available. These are capability recipes, not a required toolchain or sequence. Check available host/project/CLI/MCP capabilities first; a small audited parser or helper can be enough. Select an external provider only for the exact target, format, host and operation it has actually demonstrated. See `CAPABILITY_FIRST_TOOLING.md` for provider qualification and `EVIDENCE_QUALIFICATION.md` before promoting output.

| Reference question | Acquire the smallest useful evidence | Verify before a strong claim |
| --- | --- | --- |
| What shipped? | snapshot/hash file or directory; identify format; inventory containers, nested members, permissions, resources and variants before extraction | complete vs sampled member count, encrypted/unsupported members, parent→child byte identity and source precedence |
| Which native code or data is present? | headers, sections/segments, symbols, imports/exports, relocations, strings, xrefs, function/CFG/dataflow and selected pseudocode through an available disassembler or format parser | exact architecture, file/virtual/load mapping, parser/decompiler limits, indirect or targetless edges and uninitialized/unbacked bytes |
| What did a crash record? | original dump/core, notes, faulting thread, signal/exception, registers, stack and mapped image candidates using an offline parser or debugger | historical identity, byte ranges and module/build match; missing notes or display names do not prove absence or current identity |
| What is a managed program? | PE/CLI or equivalent metadata, types, signatures, method bodies/IL, calls, native declarations and package components through a matching reader/decompiler | metadata/IL before reconstructed source; token scope, unsupported bodies, ReadyToRun/NativeAOT/native boundary and actual runtime behavior remain separate |
| How does an app bundle connect? | ASAR/archive/package graph, entry points, main/preload/renderer or comparable processes, IPC, native add-ons, resources and configuration | unpacked sidecars, missing bytes, route/IPC candidates versus exercised messages; path conventions versus parsed metadata |
| Which JavaScript path matters? | parse identified source/bundle, find route/string/API/IPC seed, trace callers/dataflow and candidate terminal effects; optionally capture browser/Electron scripts | parser recovery, dynamic calls/properties, duplicate fingerprints, source-map pairing and static reachability versus runtime use |
| What did the UI actually do? | repeat a declared action from known state; wait for a state-specific readiness predicate; capture requested DOM/accessibility/screenshot, events, network and storage as needed | `not_requested` is not absent; an action or URL capture alone does not prove rendered state or background completion |
| What did a CLI/process do? | run authorized command in a controlled environment; capture stdin/stdout/stderr, exit/signal, child tree, timing and selected file/network before/after state | root exit versus descendant settlement, output truncation, inherited environment, cleanup/residue and process identity |
| What did a protocol exchange mean? | preserve raw packets/HAR/logs with producer version, order, endpoints, headers/bodies and framing; compare controlled cases | historical capture is not live; decoded text is not necessarily original bytes; partial trace, credential redaction and concurrent event order |
| What can mobile/firmware packaging reveal? | manifest/plist/entitlements, resources, components, nested native code or firmware regions with matching platform decoders | extracted subset is not full target; app/platform behavior, parser version, missing sidecars and unreachable regions stay explicit |

Examples of interchangeable provider classes include format-aware parsers, Ghidra/IDA/radare2-like disassemblers, managed/Android decompilers, browser developer tools/CDP, debuggers, packet analyzers, archive/asset decoders and small scripts. Their existence or installation does not prove the exact capability. If no provider can establish a material fact, keep that fact `UNKNOWN` and specify the missing capability; do not silently replace it with a model guess.

## Acquisition result contract

For each material call or helper run record: exact target and operation, provider/build/settings, host and analysis profile, input digest or live environment, exit/error/cancellation status, stdout/stderr or raw capture location, retention/truncation, effects and cleanup. Preserve valid partial observations even when execution or cleanup fails. `unsupported`, `unavailable`, `invalid input`, `permission denied`, `timeout`, `cancelled` and `resource limit` answer different questions; retain the distinction.

Large complete outputs may stay in raw storage while the agent reads stable facets/pages tied to the same run and digest. A complete page is not a complete inventory. Do not repeat an expensive acquisition merely because its first display exceeded context or transport size; use an existing retained record or a focused projection. Any export must preserve enough source identity, coverage and access information for another agent to inspect the underlying Evidence.
